## Week 2 Active Learning

- Project != ongoing operation.
- Project decomposition: Project -> Deliverable -> Work Package -> Task.
- WBS/EDT decomposes project work.
- Dependencies shape the schedule and reveal the critical path.
- Critical path is the dependent sequence that determines minimum project duration, not the most difficult work.
- Task != milestone.
- Effort != calendar duration.
- Planning -> Project Management -> Analysis is visually explicit.
- Requirements discovery flows from an understood problem through stakeholders, fact finding, candidate requirements, classification, validation and a requirements model.
- WHAT != HOW separates requirement from implementation.
- Requirement categories: Input, Process, Output, Performance and Security.
- Fact finding techniques: interview, questionnaire, observation, focus group, current-system review, process mapping and research.
- FDD decomposes business/system functions.
- WBS != FDD is presented as a project-view versus system-view distinction.
- SDLC, JAD, RAD and Agile are positioned as related but not identical categories; Forum 2.1 is ready for expansion.

## Week-1-HKA-System-Thinking Update

Added major Week 1 distinction:

SYSTEM != SOFTWARE

A system may include software, but software is only one possible component of a larger system.

Hierarchy represented:

- System -> People / Processes / Information-Data / Rules-Policies / Organization-Governance / Physical Resources / Technology.
- Technology -> Software / Digital infrastructure / Hardware infrastructure.
- Software -> Web application / Mobile application / Transactional portal / APIs-services / AI components-agents.
- Digital infrastructure -> Databases / Repositories / Knowledge libraries.

Added concept:

- Sociotechnical System

Pedagogical principle:

"Correct software does not necessarily mean a correct system."

Case layer:

- HKA Current System
- HKA People
- HKA Processes
- HKA Information
- HKA Technology
- HKA Manual Components
- HKA Resources
- Limited integration

HKA is represented as a current system with fragmented/manual/digital components and limited integration, not as "no system."

Added major reusable concept:

- Problem Framing Gate

Sequence:

Symptom -> Investigation -> Evidence -> Underlying Problem -> Alternatives -> Feasibility -> Decision -> Solution

Feedback:

- Evidence may return to problem definition.
- Feasibility may return to alternatives.
- A rejected alternative does not imply the problem disappears.
